## Recurring patterns

1. **Keyboard-first spatial state.** Across all 50 records, the stable unit of feedback is a terminal repaint: highlight, cursor, active border, title, status line, or selection-coupled detail. Motion is functional state continuity rather than decorative easing.
2. **Primary list plus contextual detail.** Git, container, Kubernetes, file, database, mail, music, network, and task products repeatedly pair a navigable collection with a detail/preview/log/status region.
3. **Persistent or discoverable command language.** Footer hints, `?`, function-key maps, command mode, and context overlays compensate for low discoverability of single-key actions.
4. **Explicit prerequisite failures.** Service-backed products expose missing daemons, clusters, accounts, devices, or endpoints in-terminal. Local file and process tools more often reach a usable first screen immediately.
5. **Reversible navigation before mutation.** Selection, focus switching, detail inspection, help, and backtracking establish confidence before destructive actions.
6. **Asynchronous refresh without ornamental transitions.** Monitors, dashboards, network tools, and service clients update values or rows in place while maintaining a spatial frame.

## Disagreements

- **Footer-first vs overlay-first help:** some interfaces reserve permanent rows for controls; others maximize content and rely on `?` or function keys.
- **Vim keys vs arrows/function keys:** many accept `j/k/h/l`; older cross-platform tools foreground arrows and F-keys; programmable products expose both.
- **Pane cycling vs mode switching:** dashboards favor Tab-like region focus, while file managers and editors treat keys as named modes with their own maps.
- **Automatic refresh vs explicit refresh:** monitoring and network tools repaint continuously; database, mail, and task tools more often require an explicit query/sync/action.
- **Failure as blocking screen vs degraded shell:** account/service products may stop at setup or connection status, while local-data tools retain navigation around an empty view.
- **Quit semantics:** `q` is common but not universal; dialogs, nested modes, and function-key conventions can consume or override it.

## Applicability boundaries

- A continuously updating dashboard should preserve selection and reading position; a static browser should not add refresh motion merely to appear alive.
- A compact footer works when the action set is small and stable; context help is preferable when bindings vary by mode or selected object.
- Color is useful for density but cannot be the only carrier of selection, severity, or completion; terminal text, cursor position, glyphs, and labels must remain.
- Backtracking keys are only trustworthy when state continuity is visible and destructive actions remain separately confirmed.
- Service-backed onboarding must name the missing prerequisite and recovery action. An empty terminal or silent retry is not an adequate first-run state.
- Terminal casts preserve timing and ANSI output but do not establish screen-reader behavior, contrast ratios, mouse parity, or reduced-motion preferences; those remain explicit unknowns in each record.
